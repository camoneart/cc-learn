サブエージェントを使うべき場面・使わない場面

2026.08.02note記事解説Claude Code

01はじめに

この記事（SubAgentの本質と分け方）では、サブエージェントを「いつ切るべきで、いつ切るべきでないのか」という運用の本質と判断基準が明確に言語化されています。

以下は、記事内で提示されている「使うべき場面」と「使わない方がよい場面」の完全なまとめです。

02使うべき場面

サブエージェントを使う判断シグナルは、次の三つに集約されます。

  • 1. 文脈を汚したくない
  • 2. 独立した作業を並列化したい
  • 3. 親の思い込みから切り離した視点が欲しい

具体例は以下の通りです。

場面 なぜ向いているか 返してほしいもの
コードベース調査 大量の検索・Read 結果を親に残さず済む 発見事項、根拠ファイル、未確認点
実装後レビュー 親の実装方針に引きずられない 指摘、重要度、修正案
コミット前検証 テスト過剰適合やエッジケース漏れを拾える 合否、失敗理由、再現手順
セキュリティ確認 専門観点で別チェックできる リスク、影響範囲、対応優先度
複数ファイルの独立修正 並列で進められる 変更内容、コンフリクト可能性
見積もり前調査 機能、既存コード、リスクを別々に探索できる 見積もり材料、リスク、前提条件

03使わない方がよい場面

一方で、次の場面ではサブエージェント化しない方がよいとされています。

場面 理由 代替
単一ファイルの小修正 起動・調査・統合コストが勝つ メインで直接処理
会話の細かい前提に依存する作業 子に前提を渡すコストが高い メインで継続
決定論的なチェック LLM に任せる必要がない hooks, CI, lint等
同じファイルを複数人で編集 コンフリクトや前提ズレが起きやすい 直列処理、明示的なタスク分割
ユーザーとの頻繁な往復が必要 子は親経由でしか戻れず、対話が鈍い メイン会話

04総評（究極の問い）

判断に迷ったら、次の問いを使います。

その作業の中間ログを、メイン会話に残したいか?

残したくないならサブエージェント候補。残したいならメインでよい。

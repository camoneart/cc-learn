context: fork と subagent: の本質

2026.08.02概念解説Claude Code

01はじめに

Claude Codeのハーネス設計において、context: fork と subagent: (agent:) はマルチエージェントオーケストレーションの根幹をなす仕組みです。

本資料では、これらの仕組みが「なぜ必要なのか」「どう使い分けるのか」を視覚的に整理します。

02context: fork とは？

context: fork は、メインの会話から一時的な別文脈（別スレッド）を分岐させるための設定です。

目的
メイン文脈の汚染防止
設定場所
SKILL.md の frontmatter
コンテキスト
親の文脈を継承する
向いている作業
検索、コード解析、試行錯誤

スキル単体で実行した場合、その過程のログ（ツールの呼び出しや試行錯誤）は全て親エージェントの記憶に残ります。context: fork を設定することで、その作業を別室で行わせ、結果だけを親に返却させることが可能になります。

03subagent: (agent:) とは？

subagent: は、そのタスクを実行する「専門家（ペルソナ）」を指名する仕組みです。

目的
専門性と役割の分離
設定場所
SKILL.md (context: fork と併用)
コンテキスト
完全に独立した状態
向いている作業
実装、レビュー、テスト作成

これを使わずに context: fork のみを実行した場合、作業者は「現在の自分（メインエージェント）」のまま別室に行くだけです。subagent: を指定することで、「フロントエンドエンジニア」や「レビュアー」といった別の人格に作業を委譲できます。

04ベストプラクティス (組み合わせ)

高度なハーネス設計では、この2つを組み合わせて使います。

推奨context: fork + subagent:

例TDDフローにおけるテスト作成
---
name: red-test-fork
context: fork
subagent: team-tester
---
# 指示
現在のコードに対してREDテストを作成してください。

このように設定することで、「親の文脈（現在のコードの状態）」を引き継ぎつつ、「テスト専門家（team-tester）」という人格で、「メインを汚さない別室」にて作業を行わせることができます。

05よくあるアンチパターン

  • context: fork の書き忘れ — スキルがメイン会話内で実行され、大量のログが親のコンテキストを圧迫（汚染）してしまう。
  • 細かすぎるサブエージェント設計 — react-hook-form-reviewer のような「知識」レベルのサブエージェントを作成してしまう（知識はSkillに逃がし、エージェントは役割・職種レベルに留めるべき）。
  • 親からの文脈渡し漏れ — 単純なサブエージェント呼び出しにおいて、親が現在開いているファイルや前提知識を渡し忘れ、サブエージェントが迷子になる。

06総評

context: fork は「作業場所（別室）」を定義し、subagent: は「作業者（専門家）」を定義する。この二つを明確に分離・連携させることが、スケーラブルでノイズのないマルチエージェント開発（ハーネスエンジニアリング）の要諦である。

03S-1.5 — fail-closed の規約と、出典の反転劇

記事のたとえは「スマホ通知のデフォルト ON」。設定し忘れた時に許可される (fail-open) か拒否される (fail-closed) かで安全性が根本から違う。ハーネスはこれを部品の役割で 3 分化した規約に精密化していた:

  • 防御 gate = fail-closed — 判定不能なら拒否側に倒す。「入力異常時の exit 0 (素通し) 禁止、特に secret・権限系」と明文規約 (hook 作成ガイドの根因 2)。
  • 観測 sensor = fail-open — センサーの故障で作業を止めない (常に exit 0)。宣言つきが 13 箇所以上。
  • 逆契約 sensor = 「沈黙しない」 — 台帳記録系は失敗を隠さない、という第 3 の契約が 1 本明文。

設計外デフォルト (allow にも deny にも無いグレーゾーン操作) は defaultMode: "default" = 人間に聞く。ここで初稿の出典が反転した: 「auto は fail-open だと自己分析して default へ切替えた記録がある」と書いたが、独立検証が原典を読むと、その 2026-05-29 ログの決定は「auto のまま + 危険操作だけ ask」= 切替を退けた記録だった。実際の切替は別リポジトリの同日ログ (Finding E) にあり、動機も「ask はモードに依存し、auto では確認窓が一度も出ず空回りしていた」という機構発見。git 履歴には auto が一度も存在しない (初回 commit から default) ことまで実測して、出典を差し替えた。

2026.08.08E-2 理由ベース vs 電報スタイル関連 issue #339

01問い — 理由を書けと言うが、書いたら膨らむのでは?

note の E-2 は「ルール列挙型ではなく理由ベース型で書け」と説く。一方、同じハーネスの CLAUDE.md 作成 skill は「電報スタイル (指示は最小限、理想 60 行未満)」を定める。理由を全ルールに書き足せば行数は膨らみ、電報スタイルに違反するのではないか — これが Dende の問いだった。

答えを先に言う: 張力は実在するが、大部分は「理由の置き場」を 3 層に分けることで両立できる。解けずに残る本物のトレードオフは 1 つだけで、それは行数の問題ではない。

02前提の訂正 — 電報スタイルは「理由禁止」ではない

電報スタイルのテンプレートの実物 (authoring-claude-md の参照資料 L203) はこうなっている:

- [ルール1]（理由: [WHY]）
- [ルール2]（理由: [WHY]）

理由込みで様式が定義されている。つまり電報スタイル違反になるのは「理由の段落化」であって「理由の併記」ではない。1 句の括弧理由は様式の内側だ。

実例も現物の CLAUDE.md にある — 「勝気なのは口調だけ。中身で見下さない・罵倒しない（Prohibition を口調が侵さないためのガード）」。理由込みで 1 行に収まっている。

03両立の 3 層 — 膨らませずに理由を持つ方法

層何をするか行数への影響
① 削除 判断基準「十分に賢ければ Claude が自発的にやることか?」が Yes ならルールごと消す。ルールが無ければ理由も要らない 減る
② ポインタ委譲 本体には 1 行「〜禁止: reference rules/decisive-answers.md」だけ置き、理由の全文と迂回封じは指し先の rule ファイルに住まわせる 変わらない
③ 短括弧インライン 電報スタイルの （理由: X）。1 句だけ、段落にしない 微増

E-2 監査で「取り入れ済み」と判定した rules/ 側が、②の受け皿として既に機能している。たとえば decisive-answers.md は理由に加えて「迂回パターン (もっともらしい言い訳) の列挙封じ」まで持つが、CLAUDE.md 側の露出は 1 行だけ。理由の総量は増やしながら、一等地 (CLAUDE.md) の行数は増やさない — これが構造の答え。

だから改修 issue #339 の処方は優先順つきになっている: 削除 > 委譲 > 短括弧追記。

04解けずに残る本物のトレードオフ — read-miss

②で委譲した理由には代償がある。ポインタの指し先は、辿られた時にしか読まれない (read-miss = 載せたのに読まれない問題)。Claude がポインタを辿るかは確率的で、読み損ねればその理由は効かない。

「必要な時 Read」の判断はモデル依存 (確率的)。読み損ねれば詳細ルールが効かない。対策として各ポインタに想起トリガーを明記し、Read 依存に耐えない核は inline 死守する。

つまり行ごとにこう問う: このルールの理由は毎セッションの判断時に必要か (→ ③でインライン死守)、それとも深掘り時だけ必要か (→ ②で委譲)。これは意味論の判断で機械化できない — #339 の実作業を「行ごとに人が確認」としたのはこのため。

要点トレードオフの正体は「行数 vs 理由」ではない

配置問題に変換できる分 (①②③) は解けている。解けない残りは 「一等地の行数」と「理由が読まれる確率」の交換。インラインに置けば必ず読まれるが行を食う。委譲すれば行は増えないが読まれるかは確率になる。この交換だけが本物のトレードオフ。

05未検証の仮説 — 痩身の時に理由が落ちた?

Dende の推測「電報スタイルを適用したから理由が書かれていないのでは」は歴史的にありそうだ。7/6〜7/8 に CLAUDE.md を 60 行へ絞る作業の記録 (before/after の HTML 2 本) が実在する。痩身の際に理由ごと削ぎ落とされた可能性は高い — ただし未検証。

#339 の作業時に git log -p -- CLAUDE.md で「理由が在った版から消えた瞬間」を探せば確定できる。もし事実なら、行数の原則 (K-2.1) の最適化が理由の原則 (E-2) を犠牲にしたという、原則同士の衝突事例として記録する価値がある。

06総評

「理由を書け」と「短く書け」は、同じ場所に書こうとするから衝突する。理由の置き場を 3 層 (削除 / 委譲 / 短括弧) に分ければ大部分は両立し、残るのは「一等地の行数」と「読まれる確率」の交換だけ — それは行ごとに人が決める。E-2 の教えの実装は、結局のところ書く技術ではなく配置の技術だった。

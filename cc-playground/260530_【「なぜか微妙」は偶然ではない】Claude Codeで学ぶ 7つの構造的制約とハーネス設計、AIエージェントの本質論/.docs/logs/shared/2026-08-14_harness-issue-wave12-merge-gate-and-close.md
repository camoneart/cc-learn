## 本波の重い発見

### 1. 「テストが赤い」と「commit が止まる」の間には推論がある (ゲートの誤判定)

ゲートは #412 に対し、統合テストの 3 件の赤を根拠に **NO-GO を出した**。測定 (base 206/0 vs PR 229/3) は正しく、2 段目が別 clone で独立再現もした。**誤りは結論の側**:

- 非ハーネスツリーでは (c) が**そもそもツリー提供ランナーを起動しない**ため、そのツリーでテストが何件赤くても (c) 由来の block は発生しない
- ハーネスツリーでは**同じテストが緑** (232/0)
- ゆえに「赤いテストが commit を止める」組合せは**どちらの場所にも存在しない**

**測ったのは「テストが赤い」までで、「だから commit が止まる」を測らずに繋いだ。** 2 段目が実 commit で反証し、ゲートは判定を公開訂正した。

### 2. 「12」の出所が「自分が今書いた文」だった (#413 H3)

`SKILL.md` の「過去 record **12 箇所**の `true` は過大申告」が実測 **10**。2 段目が 12 を産む経路も特定した — `.docs/` 全体 grep は 12 になるが、**差分 2 件は当 PR が同じ commit で足した record の散文引用**。

**自分が今書いた散文を「過去 record」として数えた形。** しかもこの行は**出力フォーマット節にあり、毎 record へ複写される**。

### 3. 契約の意味を変えると、変えていない側が block 源になる (#410 H1)

`*_count` の意味を「残存」と再定義したが、旧定義の記述が 3 箇所残った (うち 1 つは PR の diff 外)。2 段目が**実 commit で可否の反転を再現**:

- 旧定義に従って書いた record → **deny**
- 新定義に従って書いた record → **approve**

**同じレビュー・同じ事実でも、どちらの doc を読んだかで commit の可否が反転する。** レーンは 2R で PR の射程外だった `step-4-5.md` まで取り込んで解消した。

### 4. レビュアーが観測装置を汚した (#394 の実演)

1 段目レビュアーが性能測定で **base 版**の `ledger_append.sh` を隔離なしで 100 回叩き、live 台帳へ 100 行落とした。**自ら申告し、消さなかった** — 既存行の削除は #394 の HITL 未通過項目そのもので、独断削除は #66 の再発計数を壊すため。

- ゲートが独立実測: **100 行 / `08:49:30Z`〜`08:49:32Z` / 全行 `sensor=recurrence`**。過少申告も過大申告もなし
- **処置は「今は残す + #394 へ記録」** (`AskUserQuestion` 実結果。#394 `issuecomment-5278231775`)
- **皮肉な副産物**: 同じ 100 回を PR #411 版で叩くと live へ **0 行**。**当 PR の機構が効くことの独立実証**になった
- 2 段目は `HOME` ごと sandbox 化して **1174 → 1174 で完走**。同じ検証を汚さずにやれることも示された

### 5. 交差 0 でも矛盾は起きる (2 波連続で実証)

ファイル交差は 1R・2R とも **0 件**。それでも横断の不整合が 1 件出た — **レーン A が「レーン C 専管」として申し送った規律違反 2 件が、レーン C の畳んだ内訳に 1 件も入っていない (計上ゼロ)**。

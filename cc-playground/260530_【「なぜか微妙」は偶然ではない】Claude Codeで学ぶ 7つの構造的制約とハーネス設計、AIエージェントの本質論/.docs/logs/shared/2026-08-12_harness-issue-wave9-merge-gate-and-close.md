### (3) 第 2R: メインの「マージ可」判定を覆した

メインは「差し戻し条件は全件消化 + 統合テスト 66/0」で **3 本ともマージ可**と判定した。2 段目が **#382 の 2 版目実装に新規 fail-open** を検出:

```bash
# 迂回は (SKIP_GROUNDS_GATE=1 committer "<msg>" <files>) の形
committer "docs: …" rules/target.md      # ← 捏造行が入っていても ALLOW
```

**迂回の書き方をコメントに書いただけで gate が黙る。** 本 repo は迂回の逐語形を正本に複数箇所持つため実運用で踏む形。根本原因は 3 つ:

1. 判定 regex が `[;&|(]` を「コマンド位置」の目印として受け入れる — `sed` はシェルコメントを知らない
2. sentinel 退避 + 引用潰しが「1 行目の引用が閉じている」を暗黙に前提 — 閉じない引用 1 個で行境界が食われ、**heredoc 本文が 1 行目スコープへ昇格**する
3. `_BSNL` の畳み込みが sentinel 退避より先に走る

**これは base に存在しないクラス** (`channel=command` 自体が本 PR の新設)。しかも hook 本体の設計コメント「**構造的に排除できる**」「代償は**誤 deny であって誤 allow ではない**」の 2 文が**どちらも偽**だった。

## 第 3R で確立した検証の型 (次波の既定にする)

第 2R の 4 件を手順化して適用した:

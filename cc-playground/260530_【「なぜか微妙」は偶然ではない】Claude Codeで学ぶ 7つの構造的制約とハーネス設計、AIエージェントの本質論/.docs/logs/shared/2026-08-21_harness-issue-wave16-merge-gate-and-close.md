## 本波の主題 1: レビューが 4R まで伸び、伸ばしたぶんだけ実際に穴が出た

| R | 何が起きたか |
|---|---|
| 1R | 5 本すべてに指摘。**3 本に共通する構造的欠陥**を発見 (下記) |
| 2R | 5 レーン全員が修正して push。うち **2 本 (#461 #463) が再差し戻し** |
| 3R | 2 本とも修正。**#463 が再び再差し戻し** (High 1 / Medium 3 / Low 2) |
| 4R | #463 を**逆変異で独立検証**して MERGE-OK |

**「2R で全部通る」を前提にしない**のが本波の学び。2R 通過を既定にすると、3R 以降でしか出ない穴 (実装の消費側を壊す形) に永久に触れない。

### 4R の独立検証 (#463。Lead がサンドボックスで実測。worktree と `~/.claude` は 1 バイトも書いていない)

| 変異 | 期待 | rc | FAIL | 名指しされた assert |
|---|---|---|---|---|
| ベースライン | 緑 | 0 | 0 (PASS 748) | — |
| **MUT-A** 形の配列 2→1 | 赤 | **1** | **1** | `#445 射程同期: 開示が検査する形の数を書く (実装 1 形)` |
| **MUT-B** 対象配列 7→6 | 赤 | **1** | **1** | `#445 射程同期: 開示が対象本数を数値で書く (実装 6 本)` |
| **MUT-C** 配列 2 のまま / 走査だけ `[0]` | 赤 | **0** | **0** | 🔴 **鳴らなかった** |

契約 **748 PASS 0 FAIL** / orchestrator **367 PASS 0 FAIL** / 陰性対照 4 本とも名指しで緑 / 「触るな」5 件は差分ゼロ。

**MUT-C を差し戻さなかった理由 (Lead 判断)**: 走査ループの添字を `[@]` → `[0]` に書き換えるのは保守変更ではなく破壊工作で、現実に起きる変更 (形の増減・対象の増減) は MUT-A / MUT-B が覆う。
**ただし設計上の限界として残す** — **「`${#ARRAY[@]}` を doc の literal と比べる」型は、配列の消費側を壊されると必ずこの穴を持つ**。次に同じ型を書く時に効く。

> この限界は第17波で **#469 として起票した** (同ファイルに恒真式の assert が別に 1 本在ることも併せて)。

# 第12波 マージゲートのセッション運用ログ

## 概要

1 セッションで **pickup → 第12波の選抜 → レーン起動 → 1R ゲート → 2R 差し戻し → マージ 4 本 → 第13波の選抜** まで通した。前波との違いは「Critical 0 なのに High が 13 件出て、その過半が**装置自身の穴**だった」点と、**ゲート運用者の判定が 1 件まるごと反証されて公開訂正した**点。

## 内容

### 1. ゲートの型に足した 4 点

| # | 足したもの | 動機 (実際に踏んだ失敗) |
|---|---|---|
| 1 | **「壊れる」と「止まる」を分けて測る** | 統合テストの赤 3 件を根拠に NO-GO を出したが、その経路で block が実際に出るかを測っていなかった。2 段目が実 commit で反証 |
| 2 | **独立性の確保方法を波ごとに開示する** | 第11波はゲートの検算を 2 段目へ伏せた。第12波は**指摘を PR へ転記済みで伏せられない**ため「PR コメントは検証対象であって前提ではない」と発注に明記し、**独立性が前波より弱いことを開示**した |
| 3 | **2R 指示書に「直す / 直さない」を明示** | OVERSTATED を直させると過剰修正になる。#413 には「**rig を作り直すな。結論は覆っていない**」と逐語で書いた |
| 4 | **ゲート運用者の誤りを全レーンの指示書へ開示** | 「ゲートの主張も検証対象」と明記。実際にレーン C の反論でゲートの誤り 1 件が是正された |

4. 「未commit 2 件をどうする?」→ **「commit してから切る (推奨)」**
5. 「第11波 worktree 5 本の撤収、今やる?」→ **「今撤収する (推奨)」**
6. 「1 段目レビューをどの方式でやる?」→ **「fresh reviewer 4 体を並列起動 (推奨)」**

### 3. 運用者自身の失敗 5 件と検知経路の内訳

| # | 失敗 | 検知経路 |
|---|---|---|
| 1 | handoff の記載を再測せず指示書とレビュー発注へ確定形で転記 | **レーンの反論** (PR 本文) → ゲートが追認 |
| 2 | **#412 の NO-GO 判定** (測定は正しいが結論が誤り) | **2 段目の反証** (実 commit) → 公開訂正 |
| 3 | 「直接 `bash` なら 224/8」を一般化して書いた | 2 段目が再現失敗を報告 → UNVERIFIABLE |
| 4 | 背景テストを `tail -25` で回し 480 秒のログ詳細を捨てた | **自己検知** (走り直して回収) |
| 5 | 切り詰められたログで `grep -c FAIL`=0 と集計行が矛盾 | **自己検知** (空を「失敗なし」と読まなかった) |

**内訳: 外部 2 (レーン 1 / 2 段目 1) / 自己 3。** 第11波は 6 件 (外部 2 / 自己 4) だったので件数・比率とも同水準。

**質の変化**: 第11波の誤りは「時刻を測らずに書いた」等の**値の誤り**が主だったが、第12波は **2 が「推論の誤り」** — 測定は正しく、そこから導いた結論だけが偽だった。値の検算では捕まらない class で、**反証役を別に立てていなければ通っていた**。

### 4. ツール面で詰まった点 5 件

1. **`rm -rf` を含む複合コマンドが permission deny** → clone 先を毎回新しい dir 名にして回避
2. **背景実行で `>` リダイレクトを含む形も deny** → リダイレクトを外して背景実行 (出力は task ファイルへ)
3. **`sed -i` が「一括置換禁止」で block** (正しい挙動) → Edit ツールへ切替
4. **zsh で `[ "$a" \< "$b" ]` が `condition expected` で落ちる** → 交差計算を `bash -c` で撃ち直し。**空出力を「交差 0」と読まなかったのが効いた**
5. **`handoff` の frontmatter を編集した際にキー行 `blockers:` ごと消した** → 自分の検算 (`blockers = 0 件`) で気づいて復元

### 5. 停滞の性質 — レーンは「指示書を置いただけ」では動かない

2R 指示書を 4 worktree へ配置した後、**約 9 時間レーンが 1 件も動かなかった** (branch head 4 本とも 1R 時点のまま / PR コメント数も不変 / claude セッションは 4 本とも稼働中)。

原因は**プロンプト未投入**。第11波でも「判定を転記してから 5 時間レーンが無反応」を踏んでおり、**2 波連続で同じ形**。

**構造的な理由**: レーンは独立プロセスで、メインからは `SendMessage` で届かない (レーンの claude は teammate として起動していない)。指示書はファイルとして置けるが、**それを読ませる 1 手はどうしても人を経由する**。ゲート側でできるのは「貼るプロンプトを 3 行に圧縮して渡す」ところまで。

### 6. レーンの応答で質が高かった点

- **#410 が指摘の射程外まで直した** — `step-4-5.md` は PR の diff に無かったが、二重定義の解消に必要と判断して取り込んだ。さらに「**HITL 発火の基準は『検出』であって『残存』ではない**」と条件側も明確化 (原則7 の保全が理由)
- **#413 が「値を動かさない」判断を理由つきで書いた** — `scanned_skills_count: 12` を据え置き、「過去 record の 12 が別集合を指し始めるため」と明記。**直さないことの説明責任を果たした**
- **#413 がゲートの誤った前提に反論して勝った** — 指示書の「散文が計数とずれている」が base 実測で成立せず、レーンの反論が正しかった
- **レーンが申し送りを 7 本起票** — 自分の PR で閉じられないものを issue へ逃がす規律が定着している

## 設計意図

**2 段目 (反証役) を独立に立てる価値が、本波で最も明確に出た。** 1 段目の High 13 件のうち 5 件が OVERSTATED へ格下げされ、**ゲート運用者自身の NO-GO も 1 件反証された**。反証役がいなければ:

- レーンは OVERSTATED 5 件を「直すべき指摘」として処置し、過剰修正になっていた
- #412 は誤った理由でマージ保留が続いていた

**逆に、2 段目が CONFIRMED を出した 8 件はすべて 2R で是正され、マージまで到達した。** 反証を通した指摘だけを処置対象にする型が機能している。

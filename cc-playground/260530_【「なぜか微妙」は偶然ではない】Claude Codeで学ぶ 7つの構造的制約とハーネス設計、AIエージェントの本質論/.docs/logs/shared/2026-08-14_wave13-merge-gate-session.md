## ゲートの型に足したもの (第12波から)

### 1. 変異テスト — 「主張を読む」から「壊して赤くなるかを測る」へ

装置を作る PR には、**その装置を 1 点ずつ壊してテストが赤くなるか**を当てた。

- **#420**: `viol()` の先頭に `if [ "$1" = "<rule>" ]; then return 0; fi` を挿し、NO-GO トリガーを 1 つずつ黙らせた → **7 件すべて赤へ反転**、復元で 34/0
- **#422**: `validate-verdict-consistency.sh` を HEAD へ戻す → **18 assert 落下** (PR の主張と完全一致)

**レーンの木は触らない。** `git archive <ref> | tar -x -C "$(mktemp -d)"` で PR の commit を展開し、そこで変異させる。

これで **「陽性対照テストと被検査 script を同一セッションで書いた」という PR 側の構造的弱点 (#420 が自己申告)** を、レビュー側が実質的に補える。

### 2. 「問題ゼロを疑う」ために仮説を立て、**否定されたら否定の経緯も残す**

#420 で「C-1 の allowlist→理由 書き換えで `${}` / `{a,b,c}` が射程から落ちたのでは」と仮説を立てた。
実測すると **C-2 の担当** (`SKILL.md:100` + `verify-...sh:270`) で後退は無かった。

**否定された仮説もレビューコメントに書いた** — 「未開示の欠陥は検出できなかった」だけだと、探したのか探さなかったのかが読み手に分からない。

### 3. PR 監視の自動化 (`Monitor`)

60 秒間隔で `gh pr list` を回し、**新しく現れた PR 番号だけ**を stdout へ出す monitor を仕掛けた。

- レーンの PR (#420 / #422 / #423) を全部自動検知 → 待たずに他作業を進められた
- **`gh` が 3 回連続で失敗したら警告を出す**ようにした。無いと「gh が壊れて無音」と「PR が無い」が同じ沈黙になる — 本波が撃っている #408 / #415 と同じ形を監視装置自身が踏むわけにいかない

### この 9 件から見えること

- **#1 / #2 / #3 は全部「測定器が壊れていた」class**。とりわけ **#2 は偽の Critical を PR へ書く 1 歩手前**だった。第13波の指示書が冒頭に置いた「⚠ 測定器そのものを疑うこと」が、ゲート側で 3 回発火した

- **#4 は「相手の測定の方が正しかった」パターン**。ゲートが指摘する側だからといって測り方が正しいとは限らない
- **#9 は本ログを書いている最中に起きた**。「未測の値を確定形で書く」は、その失敗を記録する文章を書いている時ですら出る — **規律の自覚は再発を止めない**ことの実例

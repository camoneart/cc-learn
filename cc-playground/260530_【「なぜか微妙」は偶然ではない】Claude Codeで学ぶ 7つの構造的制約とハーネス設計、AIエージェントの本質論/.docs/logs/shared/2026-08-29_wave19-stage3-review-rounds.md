## 各Stage 詳細結果

### Stage 1R: 4 本とも NO-GO。**High 8 件はすべて fork 由来**

- **結果**: ❌ 4/4 NO-GO
- **観測**: Lead の機械検査 (`check-lane-territories.sh --verify-diff` / `pr_body_claims_check.sh --body-file`) は 4 本とも縄張り `outside=0` を返し、**High は 1 件も出なかった**。一方 fork は 8 件の High を出した。
- **学び**: **機械検査は「余計なものを触っていないか」しか見ない。** 意味論の層 (散文が実態と食い違う / 対照に判別力が無い / 分母を落とした) は fork でしか出ない。

**レンズを 2 つに割った効果 (#515 で実測)**:
- **High-1 は 2 体が独立に収束** → 信頼度が上がる
- **High-3 は片方しか発見しなかった** → 単一 fork なら落としていた

### Stage 2R: #527 の High は「直っていない」ではなく「**push されていない**」

- **結果**: ⚠️ #515/#525 は C0/H0 到達 / #516 は新 fail-open / #527 は未 push
- **観測**:
  ```
  $ git rev-parse refs/heads/issue-512 refs/remotes/origin/issue-512
  6b6a919...   ← worktree の HEAD (2R の成果)
  24b3cb8...   ← PR #527 が指す head (1R のまま)
  ```
  **17 項目中 6 項目が `6b6a919` にしか無い。** PR body は「commit 済み」と書き受入基準を `- [x]` にしていたが remote には届いていない。
- **学び**: `critical-thinking-checklist.md` の「**状態変更は成功メッセージを信じず、独立確認 (HEAD hash の変化) で landed を検証してから完了報告する**」の直撃。**レビュアーが `git ls-remote` を撃たなければ気づけなかった。**

**#516 の 2R は「是正が新しい fail-open を開けた」**:
```
validator base : ✅ CONSISTENT rc=0   ← #510 が告発した穴
validator 1R   : ❌ 不在 rc=1          ← 塞がっていた
validator 2R   : ✅ CONSISTENT rc=0   ← base へ戻った
checker  2R    : ✅ 1 件照合           ← base より悪化 (正直な WARN が偽の緑へ)
```
節終端判定を `re.split` → `_in_fence` トグルへ置き換えた結果、**閉じ忘れ fence で穴が開き直った**。
**同じファイルの 200 行下に「閉じ忘れ fence を silent にしない (第10波ゲート Medium6)」という先例規律が既に在った。**

### Stage 3R-4R: 収束を妨げる根が 1 つに特定された

- **結果**: ✅ 4 本とも C0/H0 到達。ただし Medium が残り続けた
- **観測 (#525 の 4R レビュアーの最終節、逐語)**:
  > **[MEDIUM-1] [MEDIUM-2] [LOW-1] はすべて同じ根**: 「4R が `sal:202` へ 1 行足した」→ その下の全番号が +1 →
  > head 側の値を測り直していない。**1R から 4R まで、毎ラウンド同じ根で再発している。**
  > **番号を訂正する 5R を打つと、5R の編集がまた下をずらして 6R を呼ぶ。終わらせ方は 1 つだけ** —
  > 「**語で指す形**」へ倒し、全称の申告 (「ずれ 0 件」) を **走査射程の開示**へ置き換えること。

- **Lead が再現した番号ずれの連鎖**:
  ```
  grep -n '行番号で切らない' <selection-and-launch.md>
    bef2878  → 244    (2R)
    161081d  → 245    (3R が :201 へ 1 行挿入)
    0ce5d70  → 246    (4R が :202 へ 1 行挿入)
  ```
- **学び**: **行番号を書く限りラウンドは終わらない。** 訂正が次の訂正を生む構造で、`review-and-merge.md` の「終了条件 C0/H0」だけでは Medium の無限ループを止められない。

## 重要発見

### ① Lead は間違える — 裁定ミスが 2 件、しかも 1 件はレーンに反証された

**(a) #525 の High-1 を誤って立てた (Lead が自己撤回)**

`SKILL.md:73` の「固定するのは ①②③」が #494 の層4 追加で stale になったと裁定した。**測り直したら誤り**:

```
$ git show origin/main:hooks/test/cases/test-lane-territories.sh | sed -n '14,19p'
#   **対照の本数を固定しない** — …
#   本ファイルが縛るのは次の 3 点だけ:
#     ① … ② … ③ …
```

**テストファイル自身が #494 landed 後も「縛るのは 3 点だけ」と宣言している。層の数と「縛る 3 点」は別の軸。**
**#525 の実装レンズが正しく、ドリフトレンズと Lead が誤っていた。**

**(b) #527 の差し戻し書 item 2 が誤り (レーンが実測で反証)**

Lead は「`A-Z` は照合順序ゆえ**原理的に判別できない**」と書いた。レーン H が反証:

| 対照 | 原本 rc | A-Z 変異 rc |
|---|---|---|
| `dirX/sub/test-a_b-1.sh` | 0 | **0** (判別できない) |
| `dirX/sub/Ztest-a_b-1.sh` | 0 | **2** (**判別できる**) |
| `Z` の 1 文字だけ戻した複製 | 0 | **0** |

**`Z` の 1 文字が単独の決め手。** レーン側が正しい。

**(c) Lead 由来の誤りをレーンが継承した 1 件**

#525 の PR body の fence が実出力と 1 行違うが、**その 5 行版は Lead の 1R 差し戻し書にも同じ形で在った**。
落ちた 1 行がよりによって「**本数を散文へ書かない**」= 本 PR が適用している当の規律。

> **教訓**: fork が矛盾した時に Lead が測って裁定するのは正しいが、**Lead の測り方自体を疑う経路が要る**。
> 今回は #527 の fork 2 体が独立に反証してくれたから助かった。

### ② fork の severity 申告をそのまま採らない — 格下げだけでなく**格上げ**もする

- #515 の H-2 (台帳「4 マーク」が実測 6) は **fork が Medium と申告**したが、Lead が先行行の語法を実測して **High へ引き上げた**
  - 根拠: 台帳 114 行「マーク 2 個」/ 115 行「マーク 5 個」= **物理 token 数が正本**と確定。`4` はどの読みでも成立しない
  - かつ `test-hook-authoring-guide-contract.sh` は件数を assert しない設計ゆえ**機械層が構造的に鳴らない**
- 逆に #516 は **fork が GO 推奨、Lead が NO-GO** にした
  - 理由は severity でなく「この PR の主題 (#506 = 装置の散文が装置の実態について嘘をつく) と矛盾するから」

### ③ 「面の洗い出しを全ファイルへ撃つ」の 1 面漏れが、複数 PR で同じ結果を生んだ

- #515 の Low-1: **4R の最大の追加物 (表行) を覆うパターンが 1 つも無かった**。撃っていれば Medium-1 を自分で捕まえられた
- #525 の Medium-A: **変更 3 ファイルのうち 2 本にしか撃たれていなかった**。3 本目 (record) へ撃つと 13 行ヒット

**fork の自己批判 (逐語)**:
> **「全ファイルへ撃った」は満たしているが「全変更へ撃った」は満たしていない。**

### ④ 「測っているのは症状であって性質ではない」— 掃引が false all-clear を出した実例

#515 の L-2 (`****` の是正) は `\*\*\*\*` → 0 を根拠に「解消」と記録された。**実際は閉じ側の `**` ごと消して強調が不均衡になっていた**:

| | strong 開始 | 素の `**` 残 | nested |
|---|---|---|---|
| 2R | 8 | 0 | なし ← 元は健全 |
| 3R | 10 | 2 | あり |
| **4R (head)** | **10** | **1** | **あり** ← 直っていない |
| 指示どおりの形 | 11 | 0 | なし |

**本 PR が計上している 2 つ目 bullet (測定器が対象を読めたか) そのものの形。**

### ⑤ fork が自分の懸念を能動的に反証した好例 (#527)

> 「照合順序次第で `Z` も `[a-z]` に飲まれる locale が在るのでは」と疑い、
> **`locale -a` 288 本から 16 本を選んで probe**。**全ロケールで `Z` は外側**。
> **懸念は反証された — `Z` fixture は測れた範囲で一般に効く**

「問題ゼロを疑う」規律が、**指摘を増やす方向だけでなく「自分の指摘を潰す方向」にも働いた**。

### ⑥ Monitor の設計判断が効いた — `updatedAt` でなく `headRefOid` を見る

#527 が「本文だけ編集して `updatedAt` を動かした」実例が出たので、Monitor の発火条件を `headRefOid` の変化にした。
結果、**#515 / #525 / 4 本同時 push をすべて取りこぼさずに捕捉**した。

**べた書きループも守った** (`for b in issue-506-507-509-510 issue-491-513 issue-512` — `for x in $VAR` は zsh で 1 反復)。

### ⑦ Lead 自身が L1 計上済みの罠を踏んだ (自己申告)

probe 中に:
```
$ for r in bef2878 161081d 0ce5d70; do git show $r:$P | ... ; done
(eval):1: bad substitution      ← 3 回とも取得失敗
```

**`$r:$P` が zsh の `:h` 履歴修飾に食われた。** これは `grounds-not-approval.md` 4 つ目 bullet に `#20` として計上されている形そのもの (`"$HF:hooks/…"` で `:h` に食われ `.ooks/` に化けた)。
`"${r}:${P}"` へ直したら通った。**今日ずっと「番号ずれ」を追いかけていた PR の probe で踏んだ。**

**加えて `last_updated` に未来時刻を書くミスを 2 回**した (08-25 に 19:32→22:30、08-27 に 23:48→00:30)。どちらも `date` を 1 回叩けば済む値。

## 結論

**段3 の独立 fork レビューは機能した** — High 8 件はすべて fork 由来で、Lead の機械検査からは 1 件も出なかった。レンズを 2 つに割ると片方しか見つけない High が実際に出たので、**複数レンズは冗長ではない**。

**一方で収束が遅い。** 1R→4R の全ラウンドで「訂正が新しい不正確を生む」が起き、その根の大半が「**行番号で指した / 全称で申告した**」の 2 つだった。4R のレビュアーがそれを特定して「番号を訂正する 5R を打つと 6R を呼ぶ」と明言したのが、この波で最も価値のある観測。

**Lead は 2 回間違え、2 回とも他者 (fork / レーン) に反証された。** 「Lead が測って裁定する」は必要だが十分ではなく、**その裁定を疑う経路が構造として要る**。

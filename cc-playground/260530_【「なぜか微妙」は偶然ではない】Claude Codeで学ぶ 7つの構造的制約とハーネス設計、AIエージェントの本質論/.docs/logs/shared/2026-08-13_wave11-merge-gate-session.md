# 第11波マージゲート — セッション運用ログ

> 成果 (何をマージしたか) はゲートログが持つ。本ログは**運用面** — ゲートの型がどう変わったか、HITL をどこで通したか、運用者自身が何回間違えたか、ツールのどこで詰まったか。

## 概要

第11波は 5 レーン 18 件を 2 ラウンドで完走した。本ログの目的は、**次波の運用者 (未来の自分) が同じ地雷を踏まないための運用知**を残すこと。

このセッションの特徴は 3 つ:

1. **第 1R でマージ 0 本** — 第7〜11波で初めて。Critical 1 件が「退行」だったため
2. **2 段目が 3 件を格下げした** — 第10波は覆しゼロだったので、反証工程が「形骸化していない」ことの実証になった
3. **運用者 (メイン) 自身が 7 回間違えた** — うち 6 件をゲートログの表に、1 件を本ログに記録

## 内容

### ゲートの型に足した 4 つ

| 追加 | 理由 |
|---|---|
| **1 段目の報告は回収し次第 PR へ転記する** | 第10波は転記を飛ばし、判定の一次記録を失った (PR review 0 件 / scratchpad 全滅) |
| **転記文に「2 段目の反証を経てから確定」と明記** | 転記した時点で確定判定と読まれると、レーンが誤った指摘で動く |
| **ゲート側で安く検算できる指摘は自分で撃つ。ただし結果を 2 段目へ伝えない** | アンカリング回避。本波で独立一致 3 件を得た |
| **測定器の失敗を verdict コメントへ自己申告として載せる** | 載せないと「ゲートは無謬」という誤った前提が次波へ渡る |

### 運用者自身の失敗 — 7 件の内訳

ゲートログの表 (6 件) に加え、本ログにもう 1 件足す。**全部「記録が実態からズレる」同じ形**:

| 種別 | 件数 | 内容 |
|---|---|---|
| 測れる値を測らずに書いた | 3 | `last_updated` を `17:5x` / `18:5x` と伏せ字で書いた ×2、assertion 数を 41 と書いた (実測 40) |
| 測定器が対象を見ていなかった | 3 | 素の token 検索で Critical の露出を測った / `commiter` 綴りの再演 / 非弁別 fixture |
| **直したのに古い記述を残した** | **1** | **blockers に解消済みの 4 件が残っていた。frontmatter の `ahead_count` も第10波の値のまま** |

7 件目は Stop hook が blockers を読み上げてくれたことで気づいた。**「本文を更新したが frontmatter を据え置いた」形**で、pickup 側から見ると状態が古いまま見える。

**検知経路の内訳**: 自己検知 4 / probe hook の問いかけ 1 / **2 段目レビュアー** 1 / **Stop hook** 1。**自力で全部は捕まえられていない** — 機械層と独立レビューの両方が要る。

### ツール面で詰まった 5 点 (次波でそのまま使える)

1. **`gh pr comment` の本文に commit helper の名前を含めると、heredoc で書き出す段階で `grounds-gate` が fail-closed で block する。** 回避は Write ツールでファイルを作ってから `--body-file` で渡す形。**#402 が扱っていた「散文の語で発火する」問題の、fail-closed 側の実例**

2. **`lsof -c claude` は 0 を返す壊れた測り方。** worktree を掴んでいるセッションを探すときは `pgrep -f 'claude --effort'` で pid を採り、pid ごとに `lsof -a -p <pid> -d cwd -Fn` を撃つ。この測り方に変えた瞬間に **#399 の因果の手がかり (cwd が `~/.Trash/` を指していた)** が出た

3. **background 実行の「completed (exit 0)」通知は、ラッパーの終了であってジョブの完了ではない。** `sleep 3; ...&` の形だと sleep が終わった時点で通知が飛ぶ。プロセスの生死 (`pgrep`) とログの成長 (`wc -l`) で確かめる

4. **zsh は未クォートの変数展開で語分割しない。** `committer "<msg>" $files` は 1 引数に潰れる。`files=(${(f)"$(...)"})` で配列にして `"${files[@]}"` を渡す

5. **`rm -rf` を含むコマンドは permission で拒否される。** 一時ディレクトリを作り直す時は `mktemp -d` か別名で作る

### 5 時間の停滞と、その検出

第 1R の判定を転記したあと、**差し戻し payload が中継されないまま 5 時間停滞**した。Stop hook が「handoff が 300 分前」と鳴らして気づいた。

このとき測ったもの:

```
PR head    : 5 本とも不変
worktree   : 5 本とも 未commit 0 / ahead 0
レーン内で走っているプロセス : 0 件
claude プロセス : 5 本とも生存
```

**セッションが生きているので貼れば即再開できる**、という状態を handoff に書けたのが収穫。停滞そのものより「停滞の性質」を測れたことが重要だった。

## 設計意図

**なぜ検算結果を 2 段目に伏せたか**

ゲート側で `.gitignore` 漏れ / fork のプリロード / grep パターンの 3 件を先に検算していた。伝えれば 2 段目の手間は減るが、**同じ結論に至ったのが独立の観測なのか、こちらの結論をなぞっただけなのかが区別できなくなる**。伏せた結果、3 件とも独立に一致し、その一致自体が証拠になった。

**なぜ 6 件の失敗を 2 マークに畳んだか**

再発マークは escalation の閾値判定に使う数値で、両 bullet とも既に閾値を大きく超えている (通算 6 / 4)。**6 対 2 の差が判断を変えない**以上、マーク数を膨らませるより「畳んだ事実と内訳を開示して、後から数え直せる形」を残す方が価値が高いと判断した (Lead 判断)。
